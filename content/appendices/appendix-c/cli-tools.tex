\section*{CLI Tools Reference}
\addcontentsline{toc}{section}{CLI Tools Reference}

Symphony provides command-line tools for extension development, project management, and system administration. The CLI tools are designed to support both development workflows and production deployment scenarios.

\subsection*{Carets CLI - Extension Development}

The \texttt{carets} command-line tool provides complete extension development lifecycle management:

\subsubsection*{Project Creation}

\begin{lstlisting}[language=bash,caption={Extension Project Creation}]
# Create new extension project
carets new my-extension --type=instrument --language=rust

# Available extension types
carets new my-extension --type=instrument   # AI model extension
carets new my-extension --type=operator     # Utility extension  
carets new my-extension --type=motif        # UI extension

# Language options
carets new my-extension --language=rust     # Rust extension
carets new my-extension --language=python   # Python extension
carets new my-extension --language=js       # JavaScript extension
carets new my-extension --language=wasm     # WebAssembly extension

# Template options
carets new my-extension --template=basic    # Basic template
carets new my-extension --template=ai-model # AI model template
carets new my-extension --template=ui-panel # UI panel template
\end{lstlisting}

\subsubsection*{Development Commands}

\begin{lstlisting}[language=bash,caption={Development Workflow}]
# Start development server with hot reload
carets dev

# Run with specific configuration
carets dev --config=development.toml

# Enable debug logging
carets dev --log-level=debug

# Watch specific files
carets dev --watch="src/**/*.rs"

# Run with mock Symphony environment
carets dev --mock-symphony
\end{lstlisting}

\subsubsection*{Testing Commands}

\begin{lstlisting}[language=bash,caption={Extension Testing}]
# Run all tests
carets test

# Run specific test suite
carets test --suite=unit
carets test --suite=integration
carets test --suite=e2e

# Run tests with coverage
carets test --coverage

# Run tests in watch mode
carets test --watch

# Run performance benchmarks
carets test --bench

# Test against specific Symphony version
carets test --symphony-version=1.2.0
\end{lstlisting}

\subsubsection*{Build and Package}

\begin{lstlisting}[language=bash,caption={Build and Packaging}]
# Build extension for development
carets build

# Build for production with optimizations
carets build --release

# Build for specific target platform
carets build --target=x86_64-unknown-linux-gnu
carets build --target=x86_64-pc-windows-msvc
carets build --target=x86_64-apple-darwin

# Create distribution package
carets package

# Package with specific metadata
carets package --version=1.0.0 --description="My extension"

# Sign package for distribution
carets package --sign --key-file=private.key
\end{lstlisting}

\subsubsection*{Publishing}

\begin{lstlisting}[language=bash,caption={Extension Publishing}]
# Publish to Symphony marketplace
carets publish

# Publish to specific registry
carets publish --registry=https://extensions.symphony.dev

# Publish with authentication
carets publish --token=your_auth_token

# Dry run to validate package
carets publish --dry-run

# Publish specific version
carets publish --version=1.0.0
\end{lstlisting}

\subsection*{Symphony CLI - System Management}

The main \texttt{symphony} CLI provides system-level management capabilities:

\subsubsection*{Installation and Setup}

\begin{lstlisting}[language=bash,caption={System Installation}]
# Install Symphony
symphony install

# Install specific version
symphony install --version=1.2.0

# Install with custom configuration
symphony install --config=custom-config.toml

# Verify installation
symphony doctor

# Update Symphony
symphony update

# Uninstall Symphony
symphony uninstall
\end{lstlisting}

\subsubsection*{Extension Management}

\begin{lstlisting}[language=bash,caption={Extension Management}]
# List installed extensions
symphony extensions list

# Install extension
symphony extensions install my-extension

# Install from local package
symphony extensions install ./my-extension.syx

# Install from URL
symphony extensions install https://example.com/extension.syx

# Update extension
symphony extensions update my-extension

# Remove extension
symphony extensions remove my-extension

# Enable/disable extension
symphony extensions enable my-extension
symphony extensions disable my-extension

# Show extension information
symphony extensions info my-extension
\end{lstlisting}

\subsubsection*{Configuration Management}

\begin{lstlisting}[language=bash,caption={Configuration Management}]
# Show current configuration
symphony config show

# Set configuration value
symphony config set key=value

# Get configuration value
symphony config get key

# Reset configuration to defaults
symphony config reset

# Import configuration from file
symphony config import config.toml

# Export configuration to file
symphony config export config.toml

# Validate configuration
symphony config validate
\end{lstlisting}

\subsubsection*{Workspace Management}

\begin{lstlisting}[language=bash,caption={Workspace Management}]
# Create new workspace
symphony workspace create my-project

# Open workspace
symphony workspace open /path/to/project

# List recent workspaces
symphony workspace list

# Close current workspace
symphony workspace close

# Workspace settings
symphony workspace config set key=value
symphony workspace config get key

# Workspace extensions
symphony workspace extensions list
symphony workspace extensions install extension-name
\end{lstlisting}

\subsection*{Development Tools}

Additional CLI tools for development and debugging:

\subsubsection*{Debugging Tools}

\begin{lstlisting}[language=bash,caption={Debugging Commands}]
# Start Symphony in debug mode
symphony debug

# Attach debugger to running instance
symphony debug attach --pid=12345

# Debug specific extension
symphony debug extension my-extension

# Show system logs
symphony logs

# Show logs for specific component
symphony logs --component=conductor
symphony logs --component=extension:my-extension

# Monitor system performance
symphony monitor

# Profile system performance
symphony profile --duration=60s
\end{lstlisting}

\subsubsection*{Diagnostic Tools}

\begin{lstlisting}[language=bash,caption={System Diagnostics}]
# Run system diagnostics
symphony doctor

# Check system requirements
symphony doctor --requirements

# Validate installation
symphony doctor --installation

# Check extension compatibility
symphony doctor --extensions

# Performance benchmarks
symphony benchmark

# Network connectivity tests
symphony doctor --network

# Generate diagnostic report
symphony doctor --report=diagnostic-report.json
\end{lstlisting}

\subsection*{Configuration Files}

CLI tools use various configuration files for customization:

\subsubsection*{Global Configuration}

\begin{lstlisting}[language=toml,caption={Global Configuration (symphony.toml)}]
[general]
log_level = "info"
auto_update = true
telemetry = true

[extensions]
auto_install_dependencies = true
allow_unsigned = false
marketplace_url = "https://extensions.symphony.dev"

[performance]
max_memory = "4GB"
max_cpu_cores = 8
cache_size = "1GB"

[security]
require_signatures = true
sandbox_extensions = true
allow_network_access = false

[ui]
theme = "dark"
font_size = 14
show_minimap = true
\end{lstlisting}

\subsubsection*{Extension Configuration}

\begin{lstlisting}[language=toml,caption={Extension Configuration (extension.toml)}]
[extension]
name = "my-extension"
version = "1.0.0"
description = "My custom extension"
author = "Developer Name"
license = "MIT"

[build]
target = "wasm32-unknown-unknown"
optimize = true
strip_debug = false

[dependencies]
symphony-api = "1.0"
serde = "1.0"

[permissions]
read_workspace = true
write_artifacts = true
network_access = false

[ui]
components = ["panel", "toolbar"]
themes = ["light", "dark"]
\end{lstlisting}

\subsection*{Scripting and Automation}

CLI tools support scripting and automation workflows:

\subsubsection*{Batch Operations}

\begin{lstlisting}[language=bash,caption={Batch Operations}]
# Install multiple extensions
symphony extensions install extension1 extension2 extension3

# Update all extensions
symphony extensions update --all

# Batch configuration updates
symphony config batch-set <<EOF
ui.theme=dark
editor.font_size=16
extensions.auto_update=true
EOF

# Export workspace settings
symphony workspace export-settings > workspace-config.json

# Import workspace settings
symphony workspace import-settings < workspace-config.json
\end{lstlisting}

\subsubsection*{CI/CD Integration}

\begin{lstlisting}[language=bash,caption={CI/CD Integration}]
# Non-interactive installation
symphony install --non-interactive --accept-license

# Headless testing
carets test --headless --output=junit

# Automated publishing
carets publish --token=$SYMPHONY_TOKEN --non-interactive

# Version management
carets version bump --type=patch
carets version bump --type=minor
carets version bump --type=major

# Release automation
carets release --tag=v1.0.0 --notes="Release notes"
\end{lstlisting}

These CLI tools provide support for Symphony development, deployment, and maintenance workflows, enabling both interactive development and automated CI/CD processes.
