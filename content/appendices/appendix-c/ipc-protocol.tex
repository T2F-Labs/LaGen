\section*{IPC Protocol Specification}
\addcontentsline{toc}{section}{IPC Protocol Specification}

Symphony's Inter-Process Communication (IPC) protocol enables secure, high-performance communication between the Conductor and out-of-process extensions in The Grand Stage. The protocol is built on JSON-RPC 2.0 with Symphony-specific extensions for performance optimization and security.

\subsection*{Transport Layer}

Symphony's IPC Bus supports multiple transport mechanisms optimized for different communication patterns:

\begin{description}[leftmargin=4cm,labelwidth=3.5cm]
\item[\textbf{Unix Domain Sockets}] Primary transport for general communication with 0.1-0.5ms latency
\item[\textbf{Named Pipes}] Windows-specific transport for cross-process communication
\item[\textbf{Shared Memory}] High-throughput transport for large data transfers (>1MB)
\item[\textbf{Message Queues}] Reliable delivery for critical operations requiring persistence
\end{description}

\subsection*{Message Format}

All IPC messages follow the JSON-RPC 2.0 specification with Symphony extensions:

\begin{lstlisting}[language=JSON,caption={IPC Message Structure}]
{
  "jsonrpc": "2.0",
  "id": "req_12345",
  "method": "extension.method_name",
  "params": {
    "data": "method_specific_parameters"
  },
  "symphony": {
    "version": "1.0",
    "transport": "unix_socket",
    "priority": "normal",
    "timeout": 5000,
    "trace_id": "trace_67890",
    "security_context": {
      "extension_id": "my-extension",
      "permissions": ["read_workspace", "write_artifacts"]
    }
  }
}
\end{lstlisting}

\subsection*{Request Types}

Symphony defines several categories of IPC requests:

\subsubsection*{Extension Lifecycle}

\begin{lstlisting}[language=JSON,caption={Extension Lifecycle Requests}]
// Initialize extension
{
  "jsonrpc": "2.0",
  "method": "extension.initialize",
  "params": {
    "extension_id": "my-extension",
    "workspace_path": "/path/to/workspace",
    "config": {...}
  }
}

// Shutdown extension
{
  "jsonrpc": "2.0",
  "method": "extension.shutdown",
  "params": {
    "graceful": true,
    "timeout": 10000
  }
}

// Health check
{
  "jsonrpc": "2.0",
  "method": "extension.health_check",
  "params": {}
}
\end{lstlisting}

\subsubsection*{Artifact Operations}

\begin{lstlisting}[language=JSON,caption={Artifact Operation Requests}]
// Store artifact
{
  "jsonrpc": "2.0",
  "method": "artifact.store",
  "params": {
    "content": "artifact_content",
    "metadata": {
      "type": "code",
      "language": "rust",
      "quality_score": 0.95
    }
  }
}

// Retrieve artifact
{
  "jsonrpc": "2.0",
  "method": "artifact.retrieve",
  "params": {
    "artifact_id": "sha256:abc123...",
    "include_metadata": true
  }
}
\end{lstlisting}

\subsubsection*{Event System}

\begin{lstlisting}[language=JSON,caption={Event System Requests}]
// Subscribe to events
{
  "jsonrpc": "2.0",
  "method": "events.subscribe",
  "params": {
    "pattern": "workspace.file_changed",
    "filter": {
      "file_extensions": [".rs", ".py"]
    }
  }
}

// Publish event
{
  "jsonrpc": "2.0",
  "method": "events.publish",
  "params": {
    "event_type": "extension.status_changed",
    "payload": {
      "extension_id": "my-extension",
      "status": "active"
    }
  }
}
\end{lstlisting}

\subsection*{Response Format}

IPC responses follow JSON-RPC 2.0 with Symphony-specific metadata:

\begin{lstlisting}[language=JSON,caption={IPC Response Structure}]
{
  "jsonrpc": "2.0",
  "id": "req_12345",
  "result": {
    "data": "response_data",
    "status": "success"
  },
  "symphony": {
    "execution_time": 150,
    "memory_usage": 1024000,
    "cache_hit": true,
    "trace_id": "trace_67890"
  }
}
\end{lstlisting}

\subsection*{Error Codes}

Symphony defines standardized error codes for IPC communication:

\begin{center}
\begin{tabular}{@{}lll@{}}
\toprule
\textbf{Code} & \textbf{Name} & \textbf{Description} \\
\midrule
-32700 & Parse Error & Invalid JSON received \\
-32600 & Invalid Request & Request object is invalid \\
-32601 & Method Not Found & Method does not exist \\
-32602 & Invalid Params & Invalid method parameters \\
-32603 & Internal Error & Internal JSON-RPC error \\
-32000 & Permission Denied & Insufficient permissions \\
-32001 & Resource Unavailable & Requested resource not available \\
-32002 & Timeout Error & Operation timed out \\
-32003 & Extension Error & Extension-specific error \\
-32004 & Security Violation & Security policy violation \\
\bottomrule
\end{tabular}
\end{center}

\subsection*{Security Model}

The IPC protocol implements security measures:

\subsubsection*{Authentication}

\begin{lstlisting}[language=JSON,caption={Authentication Token Structure}]
{
  "symphony": {
    "security_context": {
      "extension_id": "verified-extension",
      "signature": "base64_encoded_signature",
      "timestamp": 1640995200,
      "nonce": "random_nonce_value"

  }

\end{lstlisting}

\begin{lstlisting}[language=JSON,caption={Permission Context}]

        "write_artifacts",
        "access_ai_models"

      "resource_limits": {
        "max_memory": 1073741824,
        "max_cpu_time": 30000,
        "max_network_requests": 100
      }
    }
  }
}
\end{lstlisting}

\subsection*{Performance Optimization}

The IPC protocol includes several performance optimization features:

\subsubsection*{Message Batching}

\begin{lstlisting}[language=JSON,caption={Batch Request Format}]
{
  "jsonrpc": "2.0",
  "method": "batch",
  "params": {
    "requests": [
      {"method": "artifact.store", "params": {...}},
      {"method": "artifact.store", "params": {...}},
      {"method": "artifact.store", "params": {...}}
    ]
  }
}
\end{lstlisting}

\subsubsection*{Streaming Responses}

For large data transfers, the protocol supports streaming responses:

\begin{lstlisting}[language=JSON,caption={Streaming Response}]
{
  "jsonrpc": "2.0",
  "id": "req_12345",
  "result": {
    "stream_id": "stream_67890",
    "total_size": 10485760,
    "chunk_size": 65536
  },
  "symphony": {
    "streaming": true,
    "transport": "shared_memory"
  }
}
\end{lstlisting}

\subsection*{Protocol Extensions}

Symphony extends JSON-RPC 2.0 with additional capabilities:

\subsubsection*{Bidirectional Communication}

Extensions can initiate requests to the Conductor:

\begin{lstlisting}[language=JSON,caption={Extension-Initiated Request}]
{
  "jsonrpc": "2.0",
  "method": "conductor.request_resource",
  "params": {
    "resource_type": "ai_model",
    "model_name": "gpt-4",
    "priority": "high"
  },
  "symphony": {
    "direction": "extension_to_conductor"
  }
}
\end{lstlisting}

\subsubsection*{Heartbeat Protocol}

Automatic health monitoring through periodic heartbeat messages:

\begin{lstlisting}[language=JSON,caption={Heartbeat Message}]
{
  "jsonrpc": "2.0",
  "method": "heartbeat",
  "params": {
    "status": "healthy",
    "metrics": {
      "memory_usage": 52428800,
      "cpu_usage": 0.15,
      "active_requests": 3
    }
  }
}
\end{lstlisting}

This IPC protocol specification enables secure, high-performance communication between Symphony's components while maintaining the isolation and safety requirements of the Dual Ensemble Architecture.
