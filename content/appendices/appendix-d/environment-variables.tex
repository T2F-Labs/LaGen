\section*{Environment Variables}
\addcontentsline{toc}{section}{Environment Variables}

Symphony uses environment variables for configuration, feature flags, and runtime behavior control. Environment variables provide a secure way to configure sensitive information and enable different deployment scenarios without modifying configuration files.

\subsection*{Core System Variables}

Essential environment variables for Symphony operation:

\begin{center}
\begin{tabular}{@{}p{4cm}p{3cm}p{5cm}@{}}
\toprule
\textbf{Variable} & \textbf{Default} & \textbf{Description} \\
\midrule
\texttt{SYMPHONY\_HOME} & Platform-specific & Symphony installation directory \\
\texttt{SYMPHONY\_CONFIG} & \texttt{\$HOME/.symphony} & Configuration directory path \\
\texttt{SYMPHONY\_DATA} & \texttt{\$HOME/.symphony/data} & Data storage directory \\
\texttt{SYMPHONY\_CACHE} & \texttt{\$HOME/.symphony/cache} & Cache directory path \\
\texttt{SYMPHONY\_LOGS} & \texttt{\$HOME/.symphony/logs} & Log files directory \\
\texttt{SYMPHONY\_TEMP} & System temp & Temporary files directory \\
\bottomrule
\end{tabular}
\end{center}

\subsection*{Runtime Configuration}

Variables controlling Symphony's runtime behavior:

\begin{lstlisting}[language=bash,caption={Runtime Environment Variables}]
# Logging configuration
export SYMPHONY_LOG_LEVEL=info          # trace, debug, info, warn, error
export SYMPHONY_LOG_FORMAT=json         # json, text, pretty
export SYMPHONY_LOG_FILE=symphony.log   # Log file name
export SYMPHONY_LOG_ROTATION=daily      # daily, weekly, size

# Performance settings
export SYMPHONY_MAX_MEMORY=4GB          # Maximum memory usage
export SYMPHONY_MAX_CPU_CORES=0         # CPU cores (0 = auto-detect)
export SYMPHONY_THREAD_POOL_SIZE=8      # Thread pool size
export SYMPHONY_CACHE_SIZE=1GB          # Cache size limit

# Feature flags
export SYMPHONY_ENABLE_TELEMETRY=true   # Enable telemetry collection
export SYMPHONY_ENABLE_AUTO_UPDATE=false # Enable automatic updates
export SYMPHONY_ENABLE_CRASH_REPORTING=true # Crash reporting
export SYMPHONY_ENABLE_DEBUG_MODE=false # Debug mode

# Development settings
export SYMPHONY_DEV_MODE=false          # Development mode
export SYMPHONY_HOT_RELOAD=false        # Hot reload extensions
export SYMPHONY_MOCK_AI=false           # Use mock AI responses
export SYMPHONY_SKIP_VALIDATION=false   # Skip configuration validation
\end{lstlisting}

\subsection*{Environment Variable Precedence}

Symphony resolves configuration in the following order (highest to lowest precedence):

\begin{enumerate}
\item Command-line arguments
\item Environment variables
\item Workspace configuration files
\item User configuration files
\item System-wide configuration files
\item Built-in defaults
\end{enumerate}

\subsection*{Security Considerations}

When using environment variables for sensitive information:

\begin{itemize}
\item Use secure storage systems for API keys in production
\item Avoid logging environment variables containing secrets
\item Use variable substitution in configuration files when possible
\item Implement proper access controls for environment variable files
\item Consider using encrypted environment variable solutions
\end{itemize}

Environment variables provide flexible configuration management for Symphony while supporting secure deployment practices and development workflows across different environments and platforms.
